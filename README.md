# prime-number-rating-system

## ランキング集計（画像読み取り） — `ranking-ocr.html`

素数あつめのランキング画面のスクリーンショットをまとめて読み取って、種目ごとの順位表と JSON を作るページです。
画像はどこにも送らず、ブラウザの中だけで読み取ります（外部の AI などは使いません）。

- 見出しの種目名を見分けて、22 種目（素数ゲーム 18 種目・スコアの合計 2 種・累積 2 種）に振り分けます
- コンパクト表示（各グループの左が 1〜10 位、右が 11〜20 位）と、ふつうの表示の両方を読めます
- タイムの 4 種目（1から順に・2から順に・1桁素数・2の累乗数）は「小さいほど上」として確かめます
- 順位と点数の並びがさかさまな所や、画像によって読みがちがう所は「checking!」に出て、その行へ飛べます
- JSON には読み取れた順位だけが入ります（間が抜けていても書き出せます。checking! が残った順位は入れません）
- data.json の週の形（borders / totalBorders / lsBorders）も いっしょに書き出します
- スクロールして見出しが半透明になった画像や、iPhone の上に出る丸いものが種目名に重なった画像でも、種目を見分けます
- iOS の新しい見た目（見出しの帯の上に すき間があって帯が高い・うっすら緑の帯）でも、種目を見分けます。
  字の大きさは前と同じなので、字の上はしから前の形の帯を作りなおして くらべます
- 縮めた画像（チャットに のせた画像など）や、画面の大きさがちがう iPhone の画像でも見分けられるように、いろいろな大きさで学習してあります。
  にている種目（暗素因数分解 Lv.1/2/3・壱/参/闇、1から順に/2から順に）が近い時は、ちがう 1 文字の所だけで くらべ直します
- 種目がわからない画像（自信なしも）は、「読み取った画像」の「まとめて この種目にする」で いっぺんに種目を決めて 読み直せます（種目ごとに画像を入れる時に べんりです）
- うまく読めない時は「診断用のファイルを書き出す」で、読めなかった画像（12 枚まで）の 画面の上の所（時刻・種目名の帯）だけを 1 つのファイルにまとめられます（名前の行は入りません）
- ページのいちばん下に、この画面の版（例：2026-11-07 版）が出ます。新しい版が出たのに変わらない時は、ページを読み直してください
- 「さらに読み込む」ボタンは読みとばします
- 「あなたの順位」の欄は一覧より新しい値が出ることがあるので、順位表には混ぜずに「自分の順位」として別に出します
- 素数のスコアは緑の札（白い字）で出ます。札かどうかは「緑の中に白い字があるか」で見分けるので、札の行が多い画面（例：199・197 が続く所）でも読めます
- 300 枚以上でも軽く動くように、読み取り中の描き直しは端末の速さに合わせて間をあけます。画像一覧は「気になる画像だけ」がふだんの表示です
- 順位一覧・checking!・画像一覧は **100 ずつ ページで切りかえます**（順位一覧は 1〜100位、101〜200位…。
  「← 前の100」「次の100 →」か、ページをえらんで切りかえます。checking! から「順位一覧へ」を押すと、その順位のページに飛びます）。
  2000 位・何千枚でも 画面に出すのは 100 行だけなので、重くなりません

## ランキング分析（だれでも見られます） — `ranking-analysis.html`

公開データ（`rankings/`）を自動で読み込んで、次のことを調べられるページです。
ランキング集計の JSON を自分で読み込むこともできます（同じ週は、自分の JSON が優先です）。

- 位置しらべ：記録から「何位くらい・上位何%・偏差値いくつ」と、総合偏差値・平均偏差値・得意な種目・偏差値のならび（グラフ）
- 偏差値の目安：種目ごとに、偏差値 60・70・80 に とどくのに要る記録と、だいたいの順位
- 種目のむずかしさ（200位に入るむずかしさ・1位と100位の差・100位あたりの1つの重さ・上位1%のすごさ）
- 順位と点数のグラフ（種目どうしを「1位を100%」にそろえて くらべられます）
- RATING への影響（同じ上位%でも、種目によって もらえる「すごさ」がどうちがうか）
- 週ごとの変化
- 偏差値の出し方（式の説明・つまみで動かせる つりがね形の図・「全員が正規分布」との くらべ（上位 200・500・1000 位から その下を当てる））

RATING（`index.html`）の「分析」タブにも、同じ計算の「偏差値（概算）」カードがあります（次の目標つき）。

## 成績表 — RATING の「成績表」タブ（ホームのすぐ下）

全統模試ふうの 個人成績表です。公開データ（`rankings/`）・ボーダー（`data.json`）と、その端末の記録から作ります。

- 紙の成績表：タブを押すと、まず回の一覧が出ます（いちばん新しい回は 金色に ゆっくり光ります）
- はじめて見る回は、3つに折った紙を 下へ引っぱって ひらきます。半分より多く ひらいて 指をはなすと 最後まで ひらき、少ないと もどります
- 最後まで ひらいた しゅんかんに、その端末に「ひらいた回数」をおぼえます（`localStorage` の `sa-seki-open-v1`）。2回目からは すぐ ひらいた状態で出ます。ひらかずに ほかのタブへ行った時は 数えません
- 回：全部の順位（`rankings/`）が はじめて読めた日から、`data.json` のボーダーだけの週も 1 回として入ります
  （ボーダーだけの週は、読めていない深い順位を 近い日（28日以内）の全部の順位から借りて計算します。参加人数も 前の回から借ります）

- 総合成績：十種競技総合スコア（素数判定を除く 9 種目）の 総合偏差値・得点・全国順位・受験者数・上位%・予測平均点・予測標準偏差・評価
  （予測平均点・予測標準偏差は、受験者 全員の得点を予測して並べた時の 平均と標準偏差です）
- 種目別成績（素数ゲーム 18 種目）と、やりこみ成績（生成した乱数の累積・スコアの累積）
- 偏差値グラフ（50 を まん中に、上は青・下は だいだい）、目標判定（総合の 1000位〜1位）、次の目標、計算の注
- 偏差値・予測平均点・予測標準偏差は 小数第2位まで、全国順位は いつも出します（見つもりの時は「約」）
- 評価：S 75以上 ／ A 65以上 ／ B 60以上 ／ C 55以上 ／ D 50以上 ／ E 50未満。判定：A 到達 ／ B 差 1 未満 ／ C 2.5 未満 ／ D 5 未満 ／ E 5 以上

## 偏差値（概算）の出し方 — `rank-model.js`（v4）

ランキングには全員の点数がのっていないので、ランキングに載っている所は「順位」から出します。

1. 上位の割合　`p ＝（順位 − 0.5）÷ 参加人数 N`（参加人数は、ゲームの画面の「◯位 / ◯ プレイヤー」から読み取った人数）
2. 標準正規分布で、上から p の所の値　`z ＝ Φ⁻¹(1 − p)`
3. `偏差値 ＝ 50 ＋ 10 × z`

ランキングに載っていない所は「予測分布」から出します（v4）。

- 点数・累積：読めた いちばん下の順位 L の記録 x_L から、`x(z) ＝ x_L ×（(z − z_N) ÷ (z_L − z_N)）^κ`（z_N は 最下位 N 位の z）
  - z ＝ z_L で ちょうど x_L になり、最下位の 1 人で はじめて 0 になります（とちゅうで 0 には なりません）
  - κ（下がり方の強さ）：L から z の幅 0.4 の中の点で、`ln(x ÷ x_L)` を `ln((z − z_N) ÷ (z_L − z_N))` の 原点を通る直線で表した傾き κ̂（最小二乗）。
    ただし 点数は 4/3 以上、累積は 1/0.3 以上（`κ ＝ max(κ_min, κ̂)`。κ ＝ 4/3 は v3 の「x^(3/4) が z の直線で、最下位で 0」と同じ形）
  - `z ＝ z_N ＋ (z_L − z_N) ×（x ÷ x_L）^(1/κ)`、全国順位 ≈ `N × Q(z) ＋ 0.5`（Q は上側確率）、`偏差値 ＝ 50 ＋ 10 × z`
- タイム：`y ＝ −√x` を z の直線 `y ＝ μ ＋ σz` で表します（σ は L から z の幅 0.4 の中の点の最小二乗、直線は L を通ります）
- 読めた順位のあいだは、記録を y（点数 `x^(3/4)`・タイム `−√x`・累積 `x^0.3`）に直して、y と z を まっすぐ結びます

予測平均点・予測標準偏差は、参加者 N 人の記録を 1位から N 位まで並べたもの `x̂₁ … x̂_N` の 平均と標準偏差です。

- `r ≤ r_L`：読めた記録（抜けている順位は y と z を まっすぐ結んだ値）
- `r ＞ r_L`：`x̂_r ＝ x(z_r)`、`z_r ＝ Φ⁻¹(1 − (r − 0.5) ÷ N)`
- `予測平均点 x̄ ＝ Σ x̂_r ÷ N`、`予測標準偏差 ＝ √(Σ (x̂_r − x̄)² ÷ N)`（足し算は Neumaier の補正つきで、平均と ちらばりを 2 回に分けて足します）
- Φ⁻¹ は Wichura の AS241（相対誤差 約 10⁻¹⁶）、erfc は 級数と連分数（相対誤差 約 10⁻¹⁵）です

v3 では「x^(3/4)（累積は x^0.3）が z の直線」を そのまま下へ のばしたので、直線が 最下位より ずっと上で 0 に とどき、
「偏差値 50〜60 に要る記録が 0」になる種目がありました（2026-11-01 の スコアの累積は 78% の人が 0、など）。
v4 の形は、x^λ の いろいろな λ・v3・対数正規・対数の2次式・ロジット（上限つき）などを、次の 3 つで くらべて えらびました。

- 2026-11-01 の 1〜1000 位で「上位 200・300・500 位だけで当てはめて、その下の読めた順位を当てる」：偏差値のずれの平均 v4 1.03・0.28（K ＝ 200・500）、v3 1.17・0.37、全員が正規分布 2.63・0.79
- 累積は data.json の 1〜10000 位（16 週）で 深い所を当てる：上位 4000・5000 位から当てた時 v4 0.24・0.26、v3 1.15・1.26
- 一覧より下の記録（非公開）を当てる：v4 0.62、v3 0.85

- ◎：読めた順位で、順位がぴったり決まる所
- ○：読めた順位のあいだ（y と z を まっすぐ結んで見つもります）
- △：読めた順位より下（予測分布から出します）
- 参加人数が読めていない週は、前の週の人数を使います（`fillPlayers`。画面に「◯月◯日の人数」と出ます）

`rank-model.js` は RATING と分析ページの両方が読み込む、計算だけのファイルです（Node.js でも動きます）。

## データを すぐ読む（GitHub の いちばん新しいコミット）

RATING と 分析ページは、GitHub Pages の公開（1〜3分かかり、失敗することもあります）を待たずに、
GitHub の いちばん新しいコミット（main）の SHA を `api.github.com` に たずねて、`raw.githubusercontent.com` の「その SHA のファイル」を読みます。
`data.json`・`rankings/`・`custom-data.json` が、コミットした すぐあとから 画面に出ます。

- たずねるのは 1 分に 1 回まで（ページを開いた時・タブに入った時・画面にもどった時・5 分おき）。1 時間 60 回の回数制限に当たった時や 通信できない時は、このサイトのファイルを読みます
- コミットの ファイルの一覧も見るので、`rankings/index.json` に まだ入っていない `rankings/YYYY-MM-DD.json` や、上に直接 上げた `ranking-YYYY-MM-DD.json` も 見つけて使います
- 新しいコミットが見つかったら、データを読み直して 見ている画面を作り直します（この端末だけの一時データを使っている時は 入れかえません）

## 統計情報 — RATING の「統計情報」タブ

- 順位の動き（週ごとの変化）：集計した順位の記録が、となりあう 2 つの日のあいだに どれだけ変わったかを、赤の こさで表した図（ヒートマップ）
  - 「週ごと」：横は「前の日 → 次の日」、たては順位（上位を大きくする目盛りと ふつうの目盛り）。「種目ごと」：たては種目、横は順位
  - 色：赤 1 色で うすい → こい（大きさは 割合（%）か 差。対数の目盛りで、0 でない変化の 5%〜99% の所を うすい赤〜濃い赤）。変わっていない所は 灰色、データが無い所は 斜線
  - 「表」：マイルストーン順位 × 週の変化を、数字と 同じ赤の こさで
- マイルストーン順位：1〜10・15・20・30〜90（10 ごと）・100〜2000 位（100 ごと）の、いまの記録・前回からの変化・1 週あたりの変化・不動日数・最長の不動・変わった回数・次の順位との差（行を押すと 週ごとの記録）
- 不動日数：いまの記録を はじめて見た日から 最後に見た日までの日数（見た日どうしで くらべます）。全種目 × マイルストーン順位の 不動日数ランキングもあります
- 運営が集めたデータ：管理者が入れた項目のうち「全員に表示する」ものだけ 出します（いちばん新しい値・前回からの差・これまでの記録）

## 管理者が集めたデータ — `custom-data.json`

統計情報タブの「独自の集計データを入れる（管理者）」で、項目（タイトル・説明文・単位（なくてもよい）・全員に表示するか）を作り、日付ごとの値を入れて、
「GitHub に保存する」で このファイルに書きこみます（GitHub 連携の設定が要ります）。全員に表示しない項目の値も、ここに ずっと残ります。

```
{ "format": 1, "updated": "…", "items": [
  { "id": "…", "title": "完全制覇", "desc": "素数あつめを完全にクリアした人の数", "unit": "人", "public": true,
    "values": [ { "date": "2026-11-16", "value": 1766 } ] } ] }
```

このファイルは GitHub で だれでも開けます（「全員に表示しない」は サイトに出さない、という意味です）。

## 公開データ — `rankings/`

- `rankings/index.json`：公開している週の一覧（`latest` と `weeks: [{ date, file, categories, ranks }]`）
- `rankings/<日付>.json`：その週の全部の順位。種目ごとに `players`（参加人数）・`ranks`（順位 → 点数）・`extra`（一覧の外で読めた［順位, 点数］）
- 名前は入っていません（読み取っていません）。checking! が残った順位も入りません

## 使う流れ

1. `ranking-ocr.html` で、その週のスクリーンショットを全部読み取って、checking! を直します
2. 「JSON をダウンロード」で JSON を保存します
3. RATING の開発者メニュー →「集計の JSON を読み込む」で、その JSON を選びます（ボーダーの欄に入ります）
4. いつもどおり「GitHubに直接反映する」で data.json に反映します。
   「いっしょに公開する」に チェックが入っていれば（ふだんは入っています）、読み込んだ JSON の全部の順位も `rankings/` に書きこまれます
5. 全部の順位だけを公開する時は、同じ所の「全部の順位を公開する」を押します
   （画面の「あなたの順位」の欄は自分の記録なので、ふだんは入れません）
6. 成績表・統計情報・分析ページには、コミットした すぐあとから出ます
